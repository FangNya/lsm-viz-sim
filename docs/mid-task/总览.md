你现在是一个严谨的代码代理。以下内容是本项目的唯一可信需求来源，请严格以此为准，不要引用我未提供的开题报告，不要自行脑补工业级数据库需求，不要擅自扩展范围。

【项目定位】
这是一个用于本科毕业设计中期答辩的“教学型 LSM-Tree 可视化与交互式模拟系统”。
目标不是实现工业级数据库，而是做出一个“逻辑清楚、可演示、可观测、可复现实验”的原型系统。

【中期最小闭环】
参数配置 → 写入/查询 workload → WAL / MemTable → Flush / SSTable → Compaction → Metrics / Trace → FastAPI → WebSocket → Vue3 前端可视化

【技术栈固定】
- 后端：Python 3.11 + FastAPI + pytest
- 前端：Vue 3 + TypeScript + Vite
- 图表：ECharts
- 通信：REST API + WebSocket
- 部署：Docker Compose
- 数据存储：本地文件，不引入数据库
- 测试：后端至少 pytest；前端至少保证 build 通过

【中期必须实现】
1. 单机版 LSM-Tree 模拟器
2. put / get 基本读写流程
3. WAL + MemTable + Flush + SSTable + Bloom Filter + Compaction
4. Compaction 至少支持 STC，另做一个简化版 LCS
5. Metrics 和 Trace 导出
6. FastAPI 服务
7. Vue3 最小可演示前端
8. Docker Compose 一键启动
9. 至少两组可复现实验结果

【中期明确不做】
- 删除 / tombstone 的完整语义
- 范围查询
- 工业级并发控制
- WiscKey、Monkey、learned index
- 用户系统、权限系统、数据库接入
- 复杂 UI 美化
- RocksDB/LevelDB 级别的完整细节

【允许的简化】
- MemTable 可以先用 Python dict 实现，flush 前排序
- SSTable 可以先用 JSONL + metadata JSON 实现
- Bloom Filter 使用简化版手写实现，不引入重型依赖
- LCS 只做“教学型简化实现”，不追求工业级完整度
